# 连续输出

普通聊天、继续追问和普通对话复盘使用模型实际返回的增量。点评、动态面试、面试报告和生成题目继续完成结构化校验后展示。

## 数据链路

原链路每约 200ms 保存累计文本，SSE 每 600ms 查询任务并发送完整快照。线上实测文字按 3、133、427、591 字等批次增长，前端接收后立即显示，因此连续性主要受后端快照间隔限制。

新版在当前 API 与 Worker 同进程的部署中使用任务内存广播，及时将模型增量发给订阅者；数据库独立保存恢复点和最终结果。实时推送无需等待下一次数据库查询。没有新增模型调用、Redis 或数据表。

`/runs/:id/events?live=1` 提供新版事件。首次连接和重连先发送完整 `snapshot`，之后发送带任务、执行代次、序号及文本偏移的 `delta`。最终结果先持久化，再通知前端。没有 `live=1` 的旧页面继续使用原快照接口，可在前后端分别发布时保持兼容。

前端保留真实接收内容，使用独立的显示队列平滑呈现。显示速度随积压调整，避免生成结束后仍逐字播放很久。历史、重连和后台恢复直接同步已接收内容；终态补齐全文后切换为保存的助手消息。

## 约束

- 首字仍受模型和网络影响；应用减少的是自身的缓冲等待。
- 断线恢复必须校验序号和偏移，缺段时重新取快照；停止或切换会话后忽略旧订阅的迟到事件。
- 慢连接使用有界缓冲，不阻塞模型读取；心跳独立于数据库查询。
- 文字展示和滚动更新合并调度，保留用户上翻阅读和减少动态效果的设置。
- 当前实时广播依赖 API 与 Worker 同进程；拆分进程时需要共享事件通道。数据库快照仍用于恢复。

## 验证入口

```sh
npm test
npm run check:api
npm run test:api
npm run build
npm run test:streaming
npm run test:streaming:webkit
npm run test:e2e
```

浏览器专项使用同源 HTTP 夹具提供真实 EventSource 流，静态资源取自指定 `BASE_URL`，API 不访问真实账户或模型。部署后另用一次真实模型请求核对增量接收和 DOM 显示时间。

## 验证结果

- 前端 52 项单测、后端 55 项测试及前后端类型检查通过；新增后端测试使用真实 HTTP SSE，覆盖首批增量、重连、订阅前完成的竞争、停止末片段、慢连接、慢数据库和服务关闭。
- Chromium/WebKit 的手机和电脑流式专项各 10/10 通过。终态前可见更新约 26–42 次，覆盖原生重连、重复片段、最后代码和 emoji、停止、切会话、上翻和焦点保留。
- 生产构建完整浏览器回归通过；WebKit 另补验 24 组合成输入和 8 组输入框回缩。

手机 Chromium 实测曾发现首次点击停止按钮会触发键盘布局，按钮在按下和抬起之间移动。修为只有 textarea 聚焦才启用键盘布局后，真实触控及完整流式回归通过。首次失败报告保留为 `test-results/streaming/results-*-initial.json`。预览未启动或提前停止产生的环境失败报告也独立保留，最终结果不使用这些失败轮次。
