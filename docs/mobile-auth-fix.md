# 移动端登录与注册修复

用户在 iPhone Safari 遇到提交失败、密码输入后空白。复现确认两条独立路径：提交失败后无条件清空密码；密码管理器填入原生输入框但未触发 `input` 时，框内已有值，Vue 状态仍为空，提交发送空密码。登录与注册模式切换还会保留上一模式的错误。

提交现在读取带有 `name` 的原生表单值，兼容无事件和仅 `change` 的填充，再同步组件状态。用户名和邀请码仅去掉首尾空白；密码原样提交。失败保留密码和邀请码，成功才清理；切换模式时清除旧错误。

增加密码显示/隐藏按钮。切换前同步原生表单值，避免自动填充被状态重绘覆盖。用户名、密码和邀请码关闭自动大写、自动纠错与拼写检查，区分当前密码和新密码的自动填充用途。输入字号为 16px，触摸区域至少 44px，注册直接标明最少 12 个字符。

## 验证

`scripts/verify-auth.cjs` 完全拦截 API，使用合成账户，零真实账户写入、零模型调用。Chromium 和 WebKit 各 15 组，通过 320/390/1440 三种宽度验证：失败保留、模式切换、无事件与仅 change 的自动填充、显示隐藏、字段空格处理、成功登录注册与刷新、触摸区域及无横向溢出。

```sh
npm run test:auth
npm run test:auth:webkit
```

需预先安装 Playwright WebKit；`PLAYWRIGHT_BROWSERS_PATH` 可指定浏览器安装目录。生产浏览器回归也包含认证检查。

WebKit 引擎验证和 iPhone 尺寸模拟不等于直接控制实体 iPhone 的系统密码管理器。上线后另用真实既有学习账号，在 WebKit 上验证原生输入值提交、登录身份及刷新恢复，不调用模型，不改变已有账号密码或撤销其他设备会话。

此次仅更新静态前端，后台与数据库保留。已有 PWA 用户刷新后，如出现“新版本已准备好”，点击“保存并更新”加载修复；无需清除网站数据。
