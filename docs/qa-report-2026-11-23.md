## 修复的交互问题

| 问题                                                             | 修改后的行为                                                                                   |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 会话、笔记和题目资料弹窗焦点留在背景，Escape 不稳定              | 共用原生模态框；焦点移入、Tab 循环、背景停止滚动、关闭后返回触发按钮；嵌套 Escape 只关闭最上层 |
| AI 回复完成后发送按钮被替换，题内侧栏丢失键盘焦点                | 题内助手也使用原生模态框，回复后仍可通过 Escape 关闭                                           |
| 独立 AI 草稿被题目引用或模拟入口覆盖                             | 草稿按账号、会话、题目版本、入口、引用和模式隔离                                               |
| 请求已入队但浏览器没收到响应，刷新重试可能重复创建任务           | 保留输入与待确认请求键，刷新后重用原键；实测同一任务仅产生一条用户消息                         |
| 收藏或笔记标签改变薄弱补练范围                                   | 补练只读取真实标记为还需练习的题，不受当前标签和搜索影响                                       |
| 复核通过后原任务还显示零道通过，错误引导继续补题                 | 统计使用最新候选版本；补足请求沿用原任务的范围、题型和难度                                     |
| 题库第 2 页进入题目后返回第 1 页                                 | 页码写入路由，返回及刷新保留页码，修改搜索和分类时重置                                         |
| 个人题发布为公共题后恢复旧公共版本，个人题可能从当前内容集合消失 | 公共快照与个人内容独立合并，恢复版本和退出账号保持各自边界                                     |
| 重命名、删除、笔记读取或剪贴板失败产生未处理异常                 | 提供可见错误，保留用户可继续操作的界面                                                         |
| 旧回复失败或停止后，再次成功回答，刷新仍显示旧错误提示           | 只恢复该会话最新任务的状态；最新成功会覆盖旧提示，最新失败仍可见                               |
| 生成题保存断网后重试成功，旧连接错误仍残留                       | 新一轮保存清除旧提示；回归覆盖首次断网、再次保存、题库同步及进入练习                           |
| Windows 快捷键显示为 Mac 符号；辅助文字偏淡                      | 显示实际平台快捷键；主要辅助文字在三种基础背景的对比度从约 3.45～3.79 提高到 4.80～5.27        |

## 修复的内容与 AI 流程

| 题目                         | 修订                                                                |
| ---------------------------- | ------------------------------------------------------------------- |
| `quiz:21:3`                  | 修复读取 `undefined.x` 的 bind 示例，明确构造调用、绑定对象和返回值 |
| `quiz:21:6`                  | 区分 CommonJS 对象引用与一次取值；修正原生 ESM 导入赋值的异常类型   |
| `quiz:21:0`                  | 补清 try/await/catch 能处理异步拒绝的条件                           |
| `quiz:21:2`                  | 区分 finally 的普通兑现值、拒绝与同步抛错                           |
| `quiz:21:7`                  | 分页代码与题干的两页消费、再次 return 和清理断言一致                |
| `oral:loop:0`、`oral:loop:2` | 明确原生 JSON.parse 不能从外部暂停续跑，区分解析与可拆后处理        |
| `quiz:2:14`                  | 主回答补齐 TLS 1.3 与常见 TLS 1.2 完整握手的比较                    |

依据包括 [ECMAScript bind](https://tc39.es/ecma262/multipage/fundamental-objects.html#sec-function.prototype.bind)、[Node 模块缓存](https://nodejs.org/api/modules.html#caching)、[ECMAScript finally](https://tc39.es/ecma262/multipage/control-abstraction-objects.html#sec-promise.prototype.finally)、[JSON.parse](https://tc39.es/ecma262/multipage/structured-data.html#sec-json.parse) 和 [TLS 1.3 RFC](https://www.rfc-editor.org/rfc/rfc8446.html#section-1.2)，并执行了对应 Node 代码实验。

修订题版本为 2，题库版本为 `2026.11.23-quality.2`。旧数据库通过受信任的旧值比较升级；保留管理员修改、额外公共题、个人题、历史发布和账号记录。启动、发布及恢复共用内容写锁。遇到不同于审核旧值的字段会保留并记录冲突，不覆盖用户内容。

当前本地数据库已在无运行中任务时备份并完成升级。通过实际预览 API 核对：公共题仍为 1011 道，9 处字段全部匹配修订值，旧发布历史保留，管理账号可正常登录。本轮没有再次清理学习记录。

真实测试中曾出现非法 JSON。现在只对已完整返回但语法无效的内容尝试一次格式修复，仍需通过契约和逐题复核；网络失败不自动重发原任务，修复计入用量。第二次格式失败显示中文原因，已完成的候选保留。

点评现将实际作答放入明确的用户输入字段，区分必要改进与拓展，不再把参考解析当逐字清单。正确因果解释及明显错误各用一个真实样例验证；拓展内容不作为必要遗漏展示。用户自评与模型点评仍分别保存。

## 内容结论的范围

结构检查覆盖全部 1011 道，语义抽查覆盖 153 道，另外 858 道未逐题审定。195 道选择题中，正确选项最长占约 29.7%，最短占约 24.6%；展示顺序另由练习逻辑均衡，长度统计不能替代逐题判断。

动态 AI 输出仍有需要核实的内容。本次通过的点评样例中，拓展建议仍将 requestAnimationFrame 泛化为保证 loading 先绘制的办法；单次回调实际运行在下一次重绘之前，把耗时解析放进该回调仍可能阻塞绘制。[MDN 调度说明](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)支持这个时序区别。该建议未写入公共题库；这项生成质量边界仍保留在验收记录中，不按界面流程通过认定其事实全部正确。

本轮移动检查为 Chrome 视口及交互模拟。真实 iOS/Android 的软键盘、系统返回手势、Safari 安装及证书信任，尚未在实体设备验收。

## 再次自动化检查

重复执行单元、服务端、题库校验和生产浏览器回归。新发现的历史任务提示问题已修复，并增加四种状态组合：最新成功且更早取消、失败或结果未知时不显示旧提示；最新失败时保留失败提示。每种成功组合均检查首次打开和刷新。

另用 320/390/768/1440 四种宽度完成逐字搜索、作答、笔记收藏、刷新返回、复习笔记续写、目标持久化、备份对齐、AI 登录布局和弹窗键盘操作，保存 36 张截图；未发现页面运行异常、溢出或新的布局问题。检查账号使用独立浏览器数据。

开发服务回归曾出现一次无页面异常的空白页。连续 16 次新浏览器打开未复现；测试服务现使用独立的 Vite 依赖缓存，并在失败报告中记录控制台、请求失败和脚本响应。之后完整旅程与七组回归通过；尚未单独确认第一次空白页的原因。

真实模型串行复跑中，生成题保存流程通过；前一轮出现过一次保存连接失败及后续入口不可用，原始失败记录保留。已补充请求诊断，并用隔离夹具固定验证断网重试恢复，不把网络故障记录删除后认定从未发生。

真实模型还出现两项语义质量问题：一次普通点评把已经说明的主线程阻塞因果判为遗漏，并把数据量优化同时描述为拓展、标成遗漏；一次面试复盘声称正确的唯一递增请求序号无法区分重复输入，需要额外时间戳。前者仍未解决，不能按单次通过认定稳定可靠。后者已修订追问与复盘提示词（`2026-11-23.5`）：先核实问题前提，充分答案允许无缺口，新增条件必须明确，拓展与待验证项单独表达。

修订后直接调用同一真实模型验证了三个复盘样例：同步校验后写入的正确方案无缺口；校验后再 `await`、不复查序号的错误被识别；用户纠正错误追问前提时无缺口。一次直接探针返回非法 JSON，探针改为沿用产品已有的有界结构读取后，第三例完成验证；该探针结果只证明样例，不代表所有复盘和拓展建议均已审定。[HTML 事件循环](https://html.spec.whatwg.org/multipage/webappapis.html#event-loop-processing-model)与 [React 请求竞态示例](https://react.dev/reference/react/useEffect#fetching-data-with-effects)支持本次判定所依据的同步执行和请求身份区别。
